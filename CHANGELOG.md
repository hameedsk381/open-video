# Changelog

All notable changes to Open Video Engine. The published package is `open-video-engine` (built from `packages/ove`).

## Unreleased

### Added
- **Scene-scoped composition: many small calls instead of one big one (`OVE_COMPOSE_STRATEGY=scenes`).** The JSON route can now be composed the way a studio works: one short call agrees the *style contract* with the plan's beats (palette, fonts, a motion move per beat), one small call designs each scene against that contract and a summary of where the previous scene ends, and a deterministic stitch owns everything the models were getting wrong — durations scale the beats to the exact requested total (the model never counts frames), ids, transitions, the house camera push on every scene (which guarantees the craft checks for camera and motion), and a kinetic-split backstop on the longest scene's headline. Each call lands in the provider's fast path (0.2–2 s instead of the 12–75 s stalls big compositions hit on rate-limited gateways), fails independently — a bad scene costs its own retry with the error fed back, not the whole video — and when the renderer's review finds errors, only the scenes that own the failing frames are re-designed with the exact findings (`healScenes`). Any failure in the small-call chain falls back to the proven single-call path, so the mock provider, offline runs and the evaluation baseline are untouched. `composeByScenes` / `healScenes` in `@ove/ai` are unit-tested against a scripted provider (14 tests: contract defaults, duration scaling and the unequal-length jitter, the loader's scene-start rule, keyframe clamping, call order and handoffs, targeted heal).
- **Deep brand extraction from a URL, in the design-system-extractor tradition.** `ove agent --url` no longer guesses a brand from the homepage markup alone: the scraper now mines the site's own stylesheets and `<style>` blocks for the exact tokens the design system is written in — custom properties (a colour declared as `--primary` counts six times more than a stray hex), every colour notation normalized to `#rrggbb` (hex 3/4/6/8, `rgb()`/`rgba()` legacy and modern syntax, `hsl()`), `@font-face` declarations and font stacks (generics, `var()` indirection and length values like the `-0.01em` in `--font-letter-spacing-*` rejected) — and crawls the two highest-signal same-origin brand pages (pricing, product, about first tier; customers, blog, docs second) to confirm the palette across routes. The roles come from the evidence itself: the dominant dark non-vivid colour is the background, near-white the text, and the most-used saturated mid-tones primary, accent and secondary — a vivid indigo is never mistaken for a near-black background. Every extra request is best-effort with a per-fetch timeout, and the merged evidence (colour counts with sources, suggested roles, fonts, pages crawled) feeds the distiller prompt; without a provider the classified roles and fonts become the `BrandPack` directly, so `--url` keeps working offline with `--provider mock`. `ScrapedWebsite` gains additive fields only (`fonts`, `colorCounts`, `roles`, `pages`, `stylesheets`, `links`); the pure miners (`normalizeColor`, `mineCss`, `classifyRoles`, `pickBrandRoutes`, `mergeColorCounts`, `mergeFonts`) live in a new `@ove/ai` module and are unit-tested against real-world fixtures (Stripe's `#0a2540`/`#635bff` and Söhne come straight out of their CSS variables).
- **Named motion moves in the capability registry (registry v2).** Fourteen reusable animation patterns — `ken-burns`, `drift`, `rise-in`, `pop-in`, `blur-in`, `slide-in`, `fade-out`, `word-cascade`, `typewriter`, `pulse`, `wipe-reveal`, `parallax`, `camera-shake` and `count-up` — are registered as a new `move` kind, each with a when-to-use description, its parameters and a valid composition-JSON recipe. The planner names them in a beat's `motion` field, and the composition prompt carries a one-line glossary built from the same list, so a named move always meets the knowledge of how to build it.
- **Continuity oracle: `ove review` flags text that teleports across a hard cut.** For each scene the oracle finds where each text rests — the sampled centre it holds most often, so entrances and exits don't confuse it — and the same words resting somewhere else across a cut with no transition are a `continuity` warning naming the distance and the exact cut. Scenes joined by a transition are skipped: the transition moves everything on purpose. `continuityIssues` in `@ove/core` is pure and unit-tested.
- **The new templates meet the review bar.** The five templates added in 0.2.5–0.2.9 (`collage-broll`, `broll-loop`, `papercut-explainer`, `onetake-promo`, `logo-reveal`) were swept with the review oracle under default and mock fills: `onetake-promo`'s giant background numerals ran off the bottom edge and crossed the headline and subhead boxes (six hard errors) — they now sit below the text block in the bottom-right corner and drift there; `papercut-explainer`'s metric label no longer overlaps its badge and steps down off the kicker's size; `collage-broll`'s badge joins the type scale properly. `logo-reveal` and `broll-loop` passed as shipped.
- **Template type-scale and headline polish.** A sweep of all 17 templates under default and mock fills cleared the remaining design warnings: `case-study`'s three equal 150 px stats now read as one hero number with two supporting stats, its quote attribution and call-to-action sit on proper scale steps, and `explainer-square`/`keynote-wide` stat values no longer compete with the scene headline (`stat_grid` values scale to 5.75% of the short side instead of 8%, and `keynote-wide`'s quote steps up to match the section title). Near-equal font-size pairs were separated across `event-invite`, `product-card`, `product-wide`, `sale-promo`, `showcase-tall`, `slideshow` and `social-reel`, so every template now uses one size per step of its type scale. `quote-card`'s quotation mark no longer dips into the quote's first line when a short quote is filled in.
- **Template retiming: `--duration` now works on the template route.** A filled template whose length differs from the brief's (by more than 0.25 s) is stretched or trimmed to the requested duration: every scene's length, layer start and end frames, animation keyframes, split entrances, camera moves, scene transitions and audio fades scale by one factor, scene starts are recomputed the way the loader lays them out (each scene begins where the previous ends, minus its overlap), and rounding drift goes to the longest scene so the total is exact. Source positions (`trimStart`) are untouched — they point into the media, not the timeline — and retiming happens before narration or captions, whose word timings cannot stretch. Because the timing is then bespoke, the project is saved as a plain composition instead of an editable template, with a warning saying so. `retimeComposition` in `@ove/ai` is pure and unit-tested; `--duration` no longer forces the JSON route.
- **`ove ai shorts <long.mp4> --out dir --count 5`: the long-form → shorts factory.** The recording is transcribed once, split into sentence runs, and every window of whole sentences is scored with a transparent rubric — clean ending (2), hook in the first sentence (2), speech density (0–1), length near the 25–45 s sweet spot (0–1) — then the best non-overlapping windows are written as full vertical projects (`short-01/`, `short-02/`, …), each with the edited-reel shape from `ove ai edit` (silences and fillers tightened, word-timed captions, 1080×1920 centre-cropped). `--no-cut` keeps each short continuous; `--min`/`--max` set the window bounds. The planner is pure and unit-tested (`planShorts`/`shortsCandidatePlan` in `@ove/ai`); transcription needs a provider with `transcribe`.
- **`ove ai edit <clip> --out dir`: the talking-head editor path.** A raw clip goes in, a cleaned reel project comes out: the clip's audio is extracted and transcribed with word timings, pauses longer than `--max-silence` seconds (default 0.5), filler words (um, uh, erm…) and immediate repeats become a cut list, and the project is written as ordinary composition JSON — one `video` layer per kept stretch (`trimStart` skips the removed source, the clip's own sound plays, hard jump cuts between stretches) plus a word-timed captions layer above the platform UI band. `--width`/`--height` set the canvas (default 1080×1920, centre-cropped), `--keep-fillers` and `--no-captions` opt out. The planning is pure and unit-tested without a provider (`planCuts`/`editComposition` in `@ove/ai`); transcription needs a provider with `transcribe` (`--provider groq` or an adapter). `@ove/ffmpeg` gains `extractAudio`.
- **Safe-zone oracle: `ove review` flags text where a platform's UI covers the picture.** On a 9:16 canvas the bottom 18% (caption, audio tag, action controls) and right 11% (like/comment/share buttons) of Instagram Reels, TikTok and YouTube Shorts sit over the video, so text there is hidden in the feed; a new `safe-zone` warning names any text whose area is more than a quarter inside a band, with the exact pixels to keep clear. A wider tall canvas (4:5, square) is letterboxed in the player, so the bands shrink to where the chrome actually lands and bands that fall on the letterbox drop out; landscape canvases have no bands. `ReviewOptions.safeZone` overrides any inset (0 turns a band off) and `safeZoneBands(width, height, override?)` in `@ove/core` exposes the geometry. Narration captions default above the band on tall canvases (`narrationScene`), `social-reel`'s kickers moved below the top band (camera drift had pushed them into it), and the skill and docs document the bands.
- **Template drift: every template now clears the motion bar.** The review oracle's `frozen` check (nothing moves for 4 s or more) flagged six shipped templates — `social-reel`, `product-card`, `sale-promo`, `quote-card`, `event-invite` and `case-study` held still stretches of up to 6.5 s. Each scene in those templates now carries the house-style slow camera push the block-built templates already use (zoom 1 → 1.08 with drift easing over the scene's full length), so the picture keeps moving between beats without changing anyone's layout. The AI evaluation harness baseline moves from 3/6 to **6/6** with the mock provider, and a sweep of all 17 templates under both default and mock fills reports zero frozen windows. Remaining review warnings in templates (near-equal type sizes, three competing headlines in `case-study`/`explainer-square`/`keynote-wide`, `quote-card`'s quote mark overlapping short fills) are recorded as future polish.
- **Evaluation harness for the AI composition paths** (`scripts/eval-briefs.ts`, `pnpm eval:ai`): a fixed set of briefs — vertical promo, square product card, 4:5 flash sale, explainer, landscape launch and a fields brief that forces the JSON route — run through the real router (`composeSmart`, planner included) under identical constraints. Each run is scored with the standardized checks the agent-skill benchmark uses — composed, duration, resolution, copy readable, picture moves — plus the engine's own review findings, with optional `--render` (then the MP4 is probed) and per-brief `--only`. Scoring is route-aware: the JSON route is held to the brief's exact length, templates (which own their fixed lengths) report the delta informationally; `frozen` stays a hard check. Reports go to `artifacts/eval/report.md` and `report.json`. The mock-provider baseline is 3/6: the JSON and slideshow routes pass; three templates fail the motion bar because they hold still 4–12 seconds (`frozen`), a template-quality finding the harness now documents.
- **Skill family router delta**: the `ove` SKILL.md is now the explicit entry point — it opens with "Choose the route first" (template / JSON / React / batch-or-narration, decided with `ove ai capabilities [--json]` where the agent reads the same registry the planner validates against), names the routing contract (`--no-plan`, fallback to templates), states the artifact contract (final `composition.json`, `out.mp4`, the `review.png` contact sheet and one still per beat, so another agent or CI can audit from files), and tells third-party agents to compose *on* OVE — registry, JSON, validate → still → review — instead of re-implementing rendering.
- Fixed: the mock provider's fallback composition overlapped its subtitle with the variable-expanded title (caught by the evaluation harness's review oracle); title and subtitle no longer collide at any canvas size.
- **Unified composition planner and capability registry** (OVE 2.0 architecture): before generating, `ove ai compose` and `ove agent` ask the model for a plan — fill a template, write a JSON composition, or React code — plus what the video's beats are. The plan is validated against the capability registry (templates, themes, blocks, React components, effects, transitions and built-in sounds with their ids, params and canvas fit), so the model can only point at real capabilities; untrustworthy plans fall back to the previous template-first routing, and `--no-plan` skips planning.
- `ove ai capabilities [--json]`: list the registered capabilities the AI may use, built from the templates, themes and blocks on disk plus the built-in effects and React kit (`buildRegistry` / `planBuild` in `@ove/ai` for SDK callers; `composeSmart` in cloud jobs inherits the same routing).
- `ove agent` routes with the same planner: plain-composition briefs are produced the `ove ai compose` way (schema-checked JSON, deterministic render), and bespoke motion-graphics briefs go to the React agent loop.
- Beats from the plan are normalised to the requested duration, so a planned video always covers its full length. In `composeSmart` the plan's beats become the composition's required motion plan, so planning is never wasted.
- Fixed: `ove agent` read its arguments as raw `process.argv`, so the brief and directory were confused (the directory became the brief); arguments are now parsed from the checked argument list `index.ts` passes, and values that belong to `--option value` pairs are no longer mistaken for positionals.
- The AI Studio is now a React + Vite app (`apps/studio`) with a Vercel-style UI (light and dark, system fonts, no network needed). `pnpm build:studio` builds it into `packages/cli/studio`; `pnpm dev:studio` runs Vite against a running studio; `pnpm build:package` ships it. Without a build the studio serves the previous plain page.
- React `Video`: `layer="front"` and per-frame `left/top/width/height` (the clip moves or resizes); the build warns when it cannot scan for Audio and Video.
- React videos: `Audio`, `Video` and `Img` components (found at build time and turned into audio and video layers), and imported CSS, fonts and pictures are bundled with the component.
- Live React videos: the component is mounted in a real page each frame (React effects, refs, canvas, WebGL, three.js, d3, CSS-in-JS and other npm libraries work), then drawn through the html path with canvases captured as pictures. `delayRender()` / `continueRender()` hold a frame for async work; `config.live = false` keeps the old static-markup mode. See `examples/three-video`.
- AI Studio redesigned as a product around projects: a Projects home with thumbnails (made once, cached in `.studio`), duplicate, rename and delete (to `.trash`); a Create flow (kind, description, pictures dropped in, optional voiceover); an Editor with a live Player preview, scene jumps, and tabs for Edit (text and colour fields, or every text layer), Ask AI, Look (themes and adding blocks), History (restore) and Export (render, problem check, thumbnail); a Library; and Settings. Videos made from a template keep their variables and components, so their text stays editable by field. Studio adds `/api/projects`, `/api/project`, `/api/thumb`, `/api/library`, `/api/variables`, `/api/theme`, `/api/text`, `/api/add-block`, `/api/upload` and `/api/project/*`.
- Mattes: any layer can carry a `matte` (a video or picture you make with rembg, Robust Video Matting or an editor), shown only where the matte is white (`luma`) or opaque (`alpha`), optionally inverted. `ove track` follows the speaker through a matte. Five matte effects: neon outline, colour pop, background swap, sticker freeze, tracked label (`ove add fx-tracked-label --track track.json`).
- Colour grading: a `grade` on a layer or scene (exposure, contrast, saturation, temperature, tint, shadows, highlights, fade, or a look: warm, cool, cinematic, teal-orange, noir, vivid, faded), drawn through an SVG filter. Seven more effects: `fx-grade-look`, letterbox, shake hit, progress ring, ticker, lens flare, RGB flash.
- Studio timeline: drag scenes to move or resize them, drag a layer's left edge to trim its start, drag keyframe diamonds to retime them, Alt+arrows to nudge, snapping to the playhead.
- Effects library: 29 `fx-*` blocks (glass cards, duo title, icon orbit, stats split, spotlight, checklist, timeline, command bridge, captions, highlighter, strike and rewrite, glitch, extruded and typewriter titles, grades, light leak, clone wall, pull-out, punch-in, notifications, chat, before and after, counter hero, map journey, step tracker, split reveal, gallery, end card), a `footage` base block and the `signal` theme. `ove add --frames n` sets how long a scene or overlay lasts. `examples/effects-demo` builds a 30-second master video from them. Needs no subject matte, so neon outline, colour pop, background swap, sticker freeze and tracked label are not included.
- React videos: `open-video-engine/react` (`useCurrentFrame`, `useVideoConfig`, `Sequence`, `Series`, `AbsoluteFill`, `interpolate`, `spring`, `Easing`, `random`) and `ove build video.tsx`, which bundles the component with esbuild into a `react` layer. The renderer draws the component's markup (react-dom/server) for each frame through the html path, so frames stay exact and every other OVE feature applies. Needs `--allow-code`. See `examples/react-video`.
- Video as code: `open-video-engine/builder` (`createVideo`, layer constructors, `sample`, `spring`, `tween`, `interpolate`) builds composition JSON from TypeScript or JavaScript, and `ove build video.ts` writes it, checked with the schema. See `examples/code-video`.
- `code` layers: your own `draw(ctx, { frame, t, fps, width, height, props, api })` runs every frame on a canvas (`api.random(seed)`, `api.noise`, `api.interpolate`, `api.spring`). `Math.random` and `Date` throw so frames repeat. Because they run JavaScript, `still`, `review`, `render`, `dev`, `thumbnail`, the Player (`allowCode`) and the API (`allowCode`) refuse them unless you opt in with `--allow-code`; network access is blocked while they render; the AI commands, the Studio and workers never accept them.
- Refining a large composition (a template video, for example) sends the model a one-line-per-layer outline and takes back fixes by path, instead of the whole file both ways: about 7 KB instead of 94 KB for a four-scene video.
- AI revision history: every compose, refine, narrate, transcribe and image change is kept as a numbered revision beside the composition; `ove ai history` and `ove ai restore`, and a History list with Restore in the Studio.
- `ove thumbnail`: a cover image from any frame with an optional title, also in the Studio.
- Task skills for coding agents next to the main one: `ove-make-reel`, `ove-voiceover-captions`, `ove-batch-videos`, `ove-ai-compose`; `ove init` installs them all.
- Fixed: `ove ai refine --instruction` was refused by the strict option check.
- Blocks move and sound: slow camera pushes, drifting background shapes, push transitions, built-in sound effects, light motion blur. Four visual blocks (`phone-mockup`, `image-caption`, `icon-row`, `split-screen`) and two picture templates (`product-wide`, `showcase-tall`). `--narration` on a template video writes one voiceover line per scene and cuts the scenes to the audio. Templates take supplied pictures.
- Blocks and themes: `ove blocks`, `ove add <block> <composition.json>` and `ove theme`. Twelve reusable scenes and overlays (title, big number, quote, bullet list, numbered steps, stat grid, section divider, call to action, lower third, badge, progress bar, handle) that fit any aspect ratio, four themes, and four whole-video templates built from them (`launch-wide`, `story-tall`, `explainer-square`, `keynote-wide`). Expressions can read `canvas.width`, `canvas.height` and `canvas.fps`. The AI fills these templates and picks a theme.
- `ove ai`: provider-agnostic AI authoring (`compose`, `narrate`, `transcribe`, `image`, `batch`, `doctor`). Models write
  compositions, scripts and pictures; OVE validates every composition with the real schema, repairs it, optionally
  reviews it, then renders deterministically. Provider: Groq (chat, speech, transcription) and an offline `mock`. See `docs/ai.md`.
- `ove ai studio`: a loopback-only local page for the AI commands (brief form, live progress, rendered preview, video
  player, render), writing only inside `--out`. Requests are restricted to its own host and origin, and generated
  projects are ordinary files for `ove dev` / `ove review` / `ove render`.
- `html` layers: HTML and CSS (flexbox, grid, rich text, inline SVG) drawn as part of the frame, with no scripts and nothing fetched from the web. CSS variables can be animated with keyframes on `--name`, and `--t` places CSS `@keyframes` frame-exactly. Example: `examples/html-card`.
- `lottie` layers: Lottie animations (light player, no expressions) seeked frame-exactly, with fit, trim, speed and loop.
- `shader` layers: GLSL fragment shaders (Shadertoy `mainImage` too) with time, resolution and animatable variables as uniforms; renders use SwiftShader so pixels match on every machine.
- `layout` on groups: children placed in a row or column with gap, padding, align and justify, measured as drawn. Example: `examples/expressive`.

### Fixed
- **The older camera shorthand animates again.** Compositions — and five shipped templates — that write the scene camera as `keyframes: [{ "frame": 0, "zoom": 1.06, "easing": "drift" }]`, naming the property inside each keyframe, had that field silently dropped by the schema, which left the camera still. `loadComposition` now rewrites the shorthand into the canonical per-property `animations` form, so `broll-loop`, `collage-broll`, `logo-reveal`, `onetake-promo` and `papercut-explainer` get their camera moves back; `onetake-promo`'s corner numerals become `fixed: true` so they hold the corner while the scene zooms instead of drifting off the frame.

## 0.2.0 (2026-11-02)

### Added
- Narration-driven timing: measured media (`media[...]`) in expressions, `durationFrames: "auto"` and automatic scene placement.
- Captions layers (SRT, WebVTT, JSON word timings) with the spoken word highlighted, filler words dropped, emphasis words, and `ove captions` subtitle export.
- Audio: animated volume, ducking, `export.loudness` / `--loudness` (measured gain with a peak limiter), and built-in sound effects (`sfx:click`, `tick`, `pop`, `whoosh`, `thump`, `ding`, `riser`).
- Design: Inter built in as the default font, gradient backgrounds, film grain, role-named easings (`land`, `snap`, `glide`, `pop`, `move`, `exit`, `drift`).
- Motion: rich text spans, kinetic text (`split` by words, letters or lines), a scene camera (pan, zoom, rotate, shake) with `fixed` layers, motion blur, shape morphing, iris/push/dip/blur transitions, and a tempo beat grid (`beat()`, `bar()`, `beats()`).
- `ove review`: a contact sheet and design checks (text cut, off-frame, too small, overlapping or too brief to read; competing headlines; type scale and colours; frozen stretches; scene rhythm; transitions; caption pace; sounds cut off; loudness).
- `ove cache size` and `ove cache clean [--older-than 30d]`.
- Output quality settings: `--crf`, `--bitrate`, `--audio-bitrate`, `--scale`, `--no-motion-blur`.
- Agent skill: design guide, planning (beats, look, storyboard), story and pacing, endings.

### Changed
- **Templates are the primary AI path; compose and agent are secondary.** The planner prompt now prefers a template whenever its kind and aspect fit the brief — even when the length differs (a template keeps its own length) — so the JSON-composition and React routes trigger only for briefs no template fits. `ove ai capabilities` and the planner's capability list say so in the same words, and the docs and the `ove` skill present the template route as the default. The fallback routing was already template-first and is unchanged.
- Encoder defaults: H.264 crf 20 and H.265 crf 24, with `aq-mode=3`, to avoid banding in dark gradients.
- The drawing runtime and text layout are plain JavaScript files (`packages/graphics/runtime/`) read as text, instead of escaped template strings.
- The renderer replaces a crashed or unresponsive page and retries the frame once; errors name the frame and the layer.
- Every command checks its options: typos and options from another command stop it with a suggestion; `--name=value` is accepted. `ove review --frames` is now `--sheet-frames` (the old name still works).
- The cache folder has one subfolder per kind (`media/`, `video/`, `sfx/`); entries are marked when used. The dev server's frame cache is capped at 256 MB.
- Video layers decode only the source frames they can show, instead of from the start of the source for the whole video's length.

### Fixed
- `ove dev` refuses requests from other sites and other host names (cross-site writes to the composition, DNS rebinding).
- Distributed renders using built-in sound effects failed while mixing the soundtrack.

### Removed
- The unused `@ove/react` stub package and the no-op `pnpm build` (turbo) script.

## 0.1.0
