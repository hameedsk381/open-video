# Changelog

All notable changes to MotionRender (formerly Open Video Engine). The published package is `motionrender` (built from `packages/ove`).

## Unreleased

### Added
- **A new set of ten templates, written with a shared design kit.** The 23 earlier templates are replaced by `starter`, `hook-reel` (9:16), `kinetic-type` (9:16), `sale-flash` (9:16), `product-spotlight` (1:1), `quote-card` (1:1), `event-promo` (4:5), `logo-sting`, `stats-showcase` and `tutorial-steps` (16:9). Each takes a theme (palette, fonts, texture, motion, transition), has described variables, draws in the React view, and carries sound effects. They are generated by `pnpm build:templates` from `scripts/templates/*.mjs` (the kit is `scripts/templates/kit.mjs`), and `scripts/template-sheet.mjs <id>` renders a contact sheet to look at one. `tests/unit/shipped-templates.test.ts` checks every one. Template ids from the old set (`social-reel`, `launch-wide`, `story-tall` and the rest) no longer exist; the AI planner, the studio, the skills and the docs now point at the new ids.
- **MotionRender Studio as a desktop app (`apps/desktop`).** An Electron window around the studio the CLI already serves: it starts one `ai studio` server for the chosen project folder on a loopback port, and adds a folder card to the sidebar (the real path, Reveal, Open Folder) that appears only in the desktop build. The window is sandboxed with context isolation and Node integration off, may only navigate to its own server, and exposes a five-call bridge that takes no paths from the page. A packaged build carries ffmpeg, ffprobe and Chromium (`pnpm --filter @ove/desktop fetch-tools`; the fetched binaries and installers are git-ignored). `pnpm dev:desktop` runs it and `pnpm --filter @ove/desktop smoke` checks it end to end. Building an installer, macOS and Linux are not yet checked.
- **A production can say what it needs before it exists, and report what is still missing.** `requirements` in `production.json` name a role (a first frame, footage, a voice, a graphic…), an acquisition strategy (retrieve, source, generate, procedural), an optional instruction and a status; the schema rejects one filled by the wrong kind of file, approved with a rejected or superseded asset, or asking for the real thing but filled by a generated one. `productionCoverage` counts approvals, never files: per shot (none, blocked, review, ready), per character, environment and prop, the beats nothing is aimed at, and what is outstanding. `production validate`, the MCP tool and the plan view's next steps show it. Slice 3 of `docs/content-and-assets.md`.
- **References say what they are for.** Character, environment, prop and generation references take `{ asset, role }` as well as a bare asset id (which still works): roles are character, wardrobe, environment, product, style, storyboard, motion, first_frame, last_frame, voice, music, sfx, or the generic reference. The schema checks that a role fits the file (a first frame is not a sound), that a reference is not listed twice in one role, and that a generation has at most one first and one last frame. Slice 2 of `docs/content-and-assets.md`.
- **An asset can say where it came from, what may be done with it, and which bytes it is.** Optional fields on every asset (`provenance`, `rights`, `sha256`, `status`, `parentAssetId`), so existing compositions and productions stay valid. A generated image records its provider, model, prompt and hash, with rights left `unknown` because the provider's terms are not something the engine can know; an upload records its hash in `assets/.manifest.json`. `validate` (the CLI, the MCP tool and `production validate`) now prints notes about assets with no recorded rights, restricted or expired rights, unknown consent, and files that changed since they were recorded, and never fails on them. A version of an asset that is not declared, or an asset that is its own parent, is an error. This is slice 1 of `docs/content-and-assets.md`.
- **The review scales with the length of the video.** It samples about every half second but never more than about 400 frames, puts one frame per scene on the contact sheet when a video has more than 20 scenes (up to 48), and no longer warns that a series of a dozen or more equal-length scenes lacks rhythm. The overlay scene is left out of its rhythm and cut checks.
- **Animated highlighter on rich text.** A text layer's `highlight` (0 to 1, default 1, animatable) sweeps its span `background` highlights in left to right, one span after the next. Drawn by both the canvas runtime and the React view (36 to 38 dB against each other in a check); highlights combined with `split` stay static.
- **`overlay`: layers that stay for the whole video.** A top-level list of layers (a chapter header, a footer, a progress bar) drawn over every scene, with frames counted from the start of the video, so a header is written once instead of repeated in each scene. It takes `{{variables}}`, `repeat` and `use` like any layer list, and scene cameras and transitions never move it. On loading it becomes one last scene named `overlay`, so rendering, audio, assets, the player and the React conversion needed no change; the review leaves it out of the scene rhythm and cut checks.
- **Every video `ove ai compose` writes is a React video.** A template, a scene-by-scene composition or a catalogue block is now drawn by one shared component, `CompositionView` in `@ove/react`, and saved as the same single `react` layer a model-written video is (sound rides beside it as audio layers). The component is MotionRender's own code with the composition as data, so nothing a model wrote runs in it. It draws rectangles, circles and paths (solid or gradient fills and outlines), groups with layout (row or column, gap, padding, alignment), text (wrapped, shrunk to fit, split by word, letter or line, or rich spans with highlights and underlines), pictures, groups, animations, shadows and blur, the scene camera (zoom, drift, shake) and the fade, slide, push, wipe, zoom, dip and blur transitions. Checked against the JSON renderer on shipped templates: text and shapes land on the same pixels (glyph boxes identical to the pixel across sizes; whole frames 28 to 52 dB PSNR, the difference being anti-aliasing). Film grain, background texture, motion blur and the beat grid are carried across, since the renderer applies them to the whole frame. Small text can sit 1 to 2 px higher than the canvas draws it, because the DOM snaps baselines to whole pixels. What it cannot draw yet (video, Lottie, shader and code layers, captions, gradient text, split rich text, grading, mattes and masks, path trimming) keeps its JSON layers, and the compose note names what. `--json-layers` keeps the layers on purpose; the hosted worker still renders JSON, since a React bundle in a tenant's project is code.
- **The video is checked against what the brief asked it to say.** A required line ("end on the line: Ride more.") that no text layer says is put on the last scene, and a text layer that only names a beat ("Hook", "Problem Proof", "Call to Action") is replaced with its beat's line or dropped. Repairs are reported, `--strict` refuses them, and template results get warnings.
- **React is the default route for designed videos** where the host can run it, so a planner that answers "json" no longer turns every brief into text cards. `OVE_AI_ROUTE=planner` or `json` changes that.

### Fixed
- **Providers with a small per-request limit (Groq's on-demand tier) work through the whole pipeline.** The reserved answer room counts against the limit ("Limit 8000, Requested 10333"), so large requests used to fail and planning was skipped without saying why. The output budget now adapts to the limit the provider reports, the planner sends a short capability list for Groq (or with \`OVE_AI_COMPACT\`, or after a "too large" refusal), and Groq composes scene by scene by default, as FreeLLMAPI does.
- **A React video written outside a project now builds.** The build looked for `react` and `react-dom` only beside the video, so a generated video in a scratch folder failed with `Could not resolve "react"`; it now falls back to the copy this install resolves.
- **The React agent's repair prompts no longer grow with every attempt.** Each retry carried every earlier code and error, which pushed a provider with a small request limit (Groq's 8,000-token minute) over it. Only the brief, the latest code and the latest error go back.
- **A React video that built but was mostly blank now fails its review.** Four frames spread over the video are compared, and two identical ones are an error that names the usual cause (inside a `<Sequence>` the frame counts from the sequence's start, so an absolute start frame never arrives). The agent's prompt states the rule.
- **`ove ai compose` no longer exits 1 after a good React build.** The final write refused the folder the React route had just filled.
- **Bundled fonts work in React layers.** Only Inter did; Fraunces, DM Sans and the other families silently drew in a default serif. Every family a component names is now embedded, once per family, and nothing else is.

### Fixed
- **Replies cut off by the output limit no longer sink the whole pipeline.** Models that reason before answering spend part of the 4,096-token limit thinking and were truncated mid-answer, so planning, the script, the style contract and the composition all failed with "not valid JSON". The default is now 8,192 tokens, and a reply the model reports as cut off is asked again with twice the room, up to 32,768. `OVE_AI_MAX_TOKENS` changes the starting point.

### Removed
- **The `html` layer.** React layers are the one way to draw rich markup now. The seven `fx-*` blocks (counter hero, glass cards, highlighter, progress ring, stats split, strike rewrite, timeline) were rebuilt as React layers that draw from one shared bundle, `packages/cli/blocks/support/fx.bundle.js` (rebuild with `pnpm build:fx`); rendered frames match the html originals pixel for pixel. A block now declares the support files it needs (`files`), and `ove add`, the studio and the API copy the bundle into the project when the block is added. A file that still holds an html layer is refused with a message that says what to do, and a block added by an older version has to be added again. The `html()` builder helper, `htmlReferences` and the `examples/html-card` example are gone.

### Security
- **Hosted: a video may only use files of its own project.** A source that was an absolute path, a drive or UNC path, a `..` step or a network address was read by the render worker from the shared volume, so an account could point a picture, clip or sound at another account's file, including through a template variable or a production plan. Such sources are now refused when a project is saved and again before any render, review or thumbnail. `docs/hosting.md` also now says accurately that the render worker runs code layers (two catalogue templates use them).

### Added
- **An art director looks at React videos before they ship.** After a build passes the design review, stills from each scene go to a vision model that judges distinctiveness, hierarchy, composition and type against the brief and direction, and asks for up to two rewrites. A rewrite that fails to build or review is dropped for the version that worked. Needs a model that reads images; `OVE_AI_CRITIQUE=0` turns it off.
- **`OVE_AI_MODEL_<TASK>`** routes one kind of call (`DIRECT`, `COMPOSE`, `VISION`, …) to its own model on any provider, so the planner and direction can use a stronger model than the bulk work.

- **Ten style families and seven more fonts.** The planner and direction are shown starting points from very different visual worlds, in an order that depends on the brief, so the dark-gradient look stops being the answer to everything. Playfair Display, DM Sans, Manrope, Syne, JetBrains Mono, Bebas Neue and Instrument Serif join the five existing fonts (about 400 KB more font data per render page).
- **A brand in a compose job.** `brand` (colours and fonts, as `/api/brand/scrape` returns them) replaces the planner's palette and fonts on the template, JSON and React routes.

### Changed
- **The studio follows the look and feel of prompt-motion.com.** Light is now the default theme (a stored choice is kept): a white canvas, near-black ink, soft grey fields with no outline until focused, outline pills with a lighter count, flat showcase cards with no shadow or lift, a Home hero that is the page rather than a card, medium-weight 30 px titles and larger radii. The primary button is the ink colour (black on light, white on dark) and the blue accent is kept only for focus, selection and links. The Discover page, which was written for dark surfaces with white-alpha colours, now follows the theme; overlays on posters stay white-on-dark. The layouts, the sidebar and the editor keep their structure. Geist is not bundled, so the stack falls back to system fonts. `docs/prompt-motion-ui-guidelines.md` now says what the live site looks like; its older token tables described a dark variant.
- **Groq is the default AI provider.** With no provider named, `createProvider` uses Groq (`openai/gpt-oss-120b`) instead of the FreeLLMAPI gateway. A deployment that has only a FreeLLMAPI key and no Groq key keeps working, because with nothing named the provider that has a credential is used; naming one (`--provider`, `OVE_AI_PROVIDER`, `AI_PROVIDER`) always wins; and with no key at all it still falls back to the offline mock, now saying `GROQ_API_KEY` first. A model name no longer routes to Groq only when no gateway is configured: gemini, claude and gpt names still pick their own vendor and any other name takes the default. The hosted studio's settings page reports the provider the workers will really use instead of a fixed "FreeLLMAPI", and the Dokploy compose files pass `GROQ_API_KEY` to the web and worker services. Groq has no image generation here, so `ove ai image` and generated pictures need `--provider freellmapi` or `openai`.
- **The studio's components are redesigned around the new palette.** One filled button per view (the top-bar "New video" steps back to an outline wherever a page has its own main action, and card actions and the Play control are outlined); primary buttons are flat, with no glow or lift; cards and the Home hero are flat hairline surfaces without shadows or gradients; chips are quiet fills; the sidebar marks the current page with a neutral fill and an accent icon; workspace and preset tiles are neutral; the brand mark is a solid accent colour instead of a violet-to-cyan gradient; and the editor timeline follows the theme (it was a fixed dark slate, which made scene labels unreadable in the light theme).
- **The studio is easier to read and use.** Faint text reaches 4.5:1 on every surface in both themes (it was 3.2 to 4.4), nothing in the interface is under 12 px, the Discover search, the brief box on Create and the model picker in Settings have labels, and touch screens get 40 px controls. Shortcut hints say Ctrl on Windows and Linux and Cmd on a Mac. Home's button says "Continue" (it opens Create; it never started anything), and the editor names text slots "Eyebrow", "Headline" and "Supporting text" instead of showing layer ids such as `steps-kicker`.
- **The studio has one accent, and it is blue.** The old accent was violet (OKLCH hue 283 to 285); it is now hue 255, `#4693f1` in the dark theme (6.2:1 on the ground) and `#2474cf` in the light one (4.4:1 on the ground, 4.7:1 for a white label). Labels on the accent use the inverse ink instead of white, and toasts on the status colours too. The second token vocabulary (`--color-surface-*`, `--color-text-*`, `--color-status-*`) is gone, along with its stray fallbacks and the unrelated Tailwind blue, indigo, emerald and rose in the stylesheet and the scene lanes, which now alternate between the accent and a neutral. The active category pill had a near-white label on a white ground in the light theme; it now uses the page ink. Media stages share one `--stage` token.
- **React is the planner's default for designed videos** where the host can run it (the local studio and CLI).
- Kinetic headlines and a camera move are no longer required. The style contract chooses `motion: none` and `camera: none|push`; plan mode checks only for three scenes of unequal length and that something moves.
- The planner and creative direction run as their own `direct` task, with more headroom (2,200 tokens) and a higher first-attempt temperature for the planner (0.7), so two briefs are less likely to get the same plan.

## 0.3.15 (2026-11-07)

### Added
- **The production plan is a workspace in the studio.** Plan the film beside the timeline — brief, script beats, storyboard, shot list and a dry-run-first compile — reached from a project card or the editor. A plan scaffolds from the existing timeline, saves with field-level issues instead of a bare error, reports a conflict when another tab wrote first, and compiles into a revisioned composition without touching the timeline until applied.
- **Plans keep their own revision history.** The Revisions pane lists the timeline and `production.json` as separate sequences, with each document restorable on its own, and plan revisions summarize what changed in shots, scenes, length, beats and format.

### Changed
- **Repairs no longer cost a click on the making page.** Only unresolved review faults stop the flow and say what is wrong. A video the engine repaired opens in the editor with the repairs listed once in a dismissible banner, so warnings stay visible without holding the user on a page for a finished video.

## 0.3.14 (2026-11-07)

### Added
- **`production.json`: the film's plan, compiled to a composition.** A production manifest records what the video is meant to be — brief, style, script beats, characters, environments, props, a shot list with camera and action, assets, soundtrack, export settings and approvals — and `mr production validate` resolves every character, prop, beat and asset reference at once. `mr production compile` lays the shots end to end as scenes, hands approved takes to the renderer as footage, compiles a shot still in planning into a text card from its on-screen copy, and prints notes for anything it had to fall back on (`mr production compile --output`, MCP `motionrender_production_compile`). Shot metadata (scene, action, emotion, camera, cast, generation provenance) travels in the scene; artwork and the soundtrack carry over with the palette, fonts, texture and transitions. `examples/production-lamp` is a complete ten-second spot built this way.
- **MCP production tools.** `motionrender_production_validate` and `motionrender_production_compile` expose the manifest stage to agents, and compile's answer names the still, review and render calls to make next.
- **Content first: a validated script and its data.** A composition can now carry a `content` block — audience, promise, call to action, and the beats with spoken `narration`, on-screen copy, claims, figures and the source ids behind them — and `mr ai compose` writes that script before it designs anything. The planner, template fill, scene writer, narration and captions all derive from it, so copy is never invented during layout. Scenes can name the beat they render with `beat`, and template fills set that link when scenes and beats line up.
- **Scripts are grounded in sources.** The brief is always a source; `--source notes.md|data.csv` adds files; research (on by default, `--no-research` to skip) reads a few public pages the model names, each redirect hop checked by the SSRF guard. Every claim and figure must cite a source id, every cited source must carry a quote copied verbatim from it, and the engine verifies the quote is a literal substring before keeping the script. A rejected script is retried with the exact problem; if none survives, the video is composed without a script rather than with an unverified one. `contentSchema` enforces the same rules on imported or hand-written scripts.
- **`mr script`.** `mr script video/composition.json` prints the script and the data behind it (markdown by default, `--json` or a `.json` output for the import format), and `--set script.json` puts a revised script back after validating it and the whole composition.
- **MCP content tools.** `motionrender_create_video` takes `sources`, `research` and a `script`, and `motionrender_script` exports a video's script or imports a validated replacement.
- **A creative direction before the code.** `ove agent` now asks the model to direct the video first — concept, art direction, palette, type, motion language, sound and a beat structure with seconds — writes it to `direction.json` beside the component, and makes it the section of the coding prompt the video must realize. The stage refines the planner's idea and beats when the planner ran instead of inventing a second art direction. A direction that cannot be produced is reported and the video is still built; `--no-direction` skips the stage, and `runVideoAgent` accepts `direction: false` or a direction you wrote yourself.
- **Briefs no template or block layout can carry are written as React code.** A planner plan of `react` now reaches the agent loop from `mr ai compose` and the local studio: the component is written, compiled, visually reviewed and repaired, and handed back as an ordinary composition (`video.tsx` beside it) so review, narration and rendering are unchanged. The written script fixes the component's beats, its on-screen copy and speech, and it is saved in `composition.json` like on every other route. `--no-react` keeps the planner on data routes; a failed build falls back to a JSON composition instead of losing the job. Hosted workers are never offered this route, because the brief would otherwise choose the JavaScript the operator's machine runs.

### Changed
- **Templates are a route, not the default.** The planner is no longer told to prefer a template whenever its kind and aspect fit. It chooses template only when the scenes and look already match the brief, JSON for structured and typographic videos the blocks can express, and React when the brief asks for craft no layout carries; it is told never to force a near-miss template. The capability list and `mr ai capabilities` describe templates as ready-made layouts instead of "the primary path".
- **Narration follows the script.** A scripted video speaks its content beats — one line per scene when scenes name their beats — instead of writing a new voiceover that repeats the on-screen copy.
- **The agent no longer imposes a house style.** The React prompt dropped "The Viral Claude Standard" — a required three-scene hook/value/CTA, Badge/KineticText/whoosh, GlassCard/bento/ticker/pop, DeviceFrame/ding and a continuous zoom — along with "always include AmbientGlow" and the reel rule that mandated BentoGrid, KineticText, GlassCard and AmbientGlow. The component kit is now optional resources, and design authorship is a principle: choose the composition, type, colour and motion this brief deserves. Safe zones and supplied brand tokens remain requirements, because those are constraints rather than style.

## 0.3.13 (2026-11-07)

### Added
- **The model decides the design.** Video generation no longer starts from one house style. The planner returns an art direction — display and body font, palette, texture, motion preset, transition, layout and density — that the composition follows, and free-form scene writing carries the same direction through every scene instead of being told to build a dark gradient with near-white text.
- **Five bundled typefaces.** Inter, Space Grotesk, Fraunces, Archivo and Source Sans 3 ship with the renderer and are offered to themes and the planner, so a video can set a tone the single previous face could not.
- **Seventeen theme tokens.** Themes now choose typography, background texture, motion preset, transition, layout and density alongside colour and radius, and the five presets have distinct voices rather than the same look in different colours. Compositions can also draw a top-level `texture` (grid, dots, scanlines or paper).
- **Layout variants on core blocks.** Title, big-stat and call-to-action blocks take `left`/`center`/`band`, `center`/`left`/`split` and `center`/`left`/`panel`; themed templates pick a variant per template, so openings and closes are no longer one assembly of the same blocks.
- **Testimonial template.** A 7-second, square (1080×1080) customer testimonial: a five-star rating, the quote revealed line by line, and an initials avatar with the customer's name and company. It takes every theme like the other card templates and is meant for batch generation, one video per customer.
- **`pnpm check:templates`.** Resolves and reviews every shipped template with the renderer — design, safe zones and loudness — and fails on any error or warning, so the catalogue cannot regress into a layout that cuts text or plays too quietly. CI runs it on Linux.

### Fixed
- **Documented `mr ai` options are accepted.** The argument checker rejected options the AI commands read and the help lists — `--theme`, `--typography`, `--motion-pacing`/`--pacing`, `--audio-mood`/`--mood`, `--voice-tone`, `--cta`, `--sfx`, `--lang`, `--max-silence`, `--keep-fillers`, `--no-cut`, `--width`, `--height`, `--count`, `--min`, `--max` — with "does not take". They now pass validation.
- **Refinements report their notes.** Studio's *AI Director* pane now shows the warnings a refine returns instead of discarding them, so a change that only applied after the engine repaired something is not presented as a clean success.
- **An explicit reel gets the reel safe zones.** Choosing `format: 'reel'` without a reel-shaped brief used to skip the platform safe-zone rules in the agent prompt; the bands now follow the video's shape, not how the shape was chosen.
- **Brand scraping checks every URL it fetches.** The API passed its SSRF guard only the entry URL, so a redirect, a linked stylesheet or a crawled page could still point at an internal address. Redirects are now followed manually with each hop, stylesheet and crawl target checked before the request. Scraped copy is fenced as untrusted data in the distiller prompt, and the BrandPack it yields is limited to literal hex colours, single-line bounded text and CSS-shaped font names, so page content cannot turn into prompt text for the video generator.
- **Template fills are reviewed.** With `review` on, a filled template now goes through the same renderer design review as a written composition: errors and warnings reach the host, and Studio's creation screen reports them instead of redirecting to a video the review still faults. A review that cannot run marks the video unchecked rather than discarding it.
- **An explicit template keeps its canvas.** A named template (`--template` or Studio's picker) is filled even when the brief's aspect differs, because the layout only works at its own size; an unknown id fails with the list of available templates instead of quietly writing a different video.
- **Template catalogue fixes.** The quiet audio templates now normalise to `export.loudness: -14` (including a peak-safe logo sting), the event invite uses four text colours instead of six, the slideshow and launch-wide/story-tall title scenes hold their copy long enough to read, the social reel's hook line is shorter, and the one-take promo's second watermark no longer runs off the frame.

### Changed
- **The planner is a creative director.** Its prompt asks for a look and explains the bundled families, layouts, textures and motion presets; a look that the validator cannot use is dropped field by field instead of costing the plan, and the template path applies it over the theme without overriding copy. Fixed near-white ink, muted grey and dark-gradient instructions are gone from the composition prompt — flat and light palettes are valid whenever the look calls for them.
- **The Vercel AI SDK is now the only network integration layer.** The hand-rolled HTTP clients for Groq, Anthropic, NVIDIA and FreeLLMAPI are gone: every provider — `groq`, `anthropic`/`claude`, `nvidia`/`nim`, `freellmapi` (the default), `openai`, `google`/`gemini`, `openrouter`, `litellm`, `custom` and any OpenAI-compatible base URL — is the same `VercelAiProvider` riding `generateText`, `generateImage` and `transcribe` from the `ai` package, with per-vendor drivers and defaults. Retries (429/5xx ×2 with backoff), timeouts and message shaping are now the SDK's consistent behavior everywhere. What survives in `providers.ts` is policy, not plumbing: the FreeLLMAPI task-aware model routing (`TASK_MODEL_PREFERENCES`, live model-list discovery, the `auto` fallback) still picks each task's preferred model, and transcription forces `response_format: 'verbose_json'` through provider options so gateway model ids like `auto` still return word timestamps. The unstable gateway JSON mode is no longer requested at all — the tolerant `extractJson` parser was already doing that work. Speech stays Edge TTS for every provider (it was already the default engine), the mock provider and the offline pipeline are untouched, and `OVE_AI_SPEECH_MODEL` (a Groq-only concept) is retired along with the `engine: 'vercel'` opt-in — there is no other engine left.

## 0.3.2 (2026-11-05)

### Added
- **MotionRender rebrand.** Rebranded CLI, runtime, packages, and studio to MotionRender (`motionrender`).
- **Scene-scoped composition: many small calls instead of one big one (`OVE_COMPOSE_STRATEGY=scenes`).** The JSON route can now be composed the way a studio works: one short call agrees the *style contract* with the plan's beats (palette, fonts, a motion move per beat), one small call designs each scene against that contract and a summary of where the previous scene ends, and a deterministic stitch owns everything the models were getting wrong — durations scale the beats to the exact requested total (the model never counts frames), ids, transitions, the house camera push on every scene (which guarantees the craft checks for camera and motion), and a kinetic-split backstop on the longest scene's headline. Each call lands in the provider's fast path (0.2–2 s instead of the 12–75 s stalls big compositions hit on rate-limited gateways), fails independently — a bad scene costs its own retry with the error fed back, not the whole video — and when the renderer's review finds errors, only the scenes that own the failing frames are re-designed with the exact findings (`healScenes`). Any failure in the small-call chain falls back to the proven single-call path, so the mock provider, offline runs and the evaluation baseline are untouched. `composeByScenes` / `healScenes` in `@ove/ai` are unit-tested against a scripted provider (14 tests: contract defaults, duration scaling and the unequal-length jitter, the loader's scene-start rule, keyframe clamping, call order and handoffs, targeted heal).
- **Deep brand extraction from a URL, in the design-system-extractor tradition.** `ove agent --url` no longer guesses a brand from the homepage markup alone: the scraper now mines the site's own stylesheets and `<style>` blocks for the exact tokens the design system is written in — custom properties (a colour declared as `--primary` counts six times more than a stray hex), every colour notation normalized to `#rrggbb` (hex 3/4/6/8, `rgb()`/`rgba()` legacy and modern syntax, `hsl()`), `@font-face` declarations and font stacks (generics, `var()` indirection and length values like the `-0.01em` in `--font-letter-spacing-*` rejected) — and crawls the two highest-signal same-origin brand pages (pricing, product, about first tier; customers, blog, docs second) to confirm the palette across routes. The roles come from the evidence itself: the dominant dark non-vivid colour is the background, near-white the text, and the most-used saturated mid-tones primary, accent and secondary — a vivid indigo is never mistaken for a near-black background. Every extra request is best-effort with a per-fetch timeout, and the merged evidence (colour counts with sources, suggested roles, fonts, pages crawled) feeds the distiller prompt; without a provider the classified roles and fonts become the `BrandPack` directly, so `--url` keeps working offline with `--provider mock`. `ScrapedWebsite` gains additive fields only (`fonts`, `colorCounts`, `roles`, `pages`, `stylesheets`, `links`); the pure miners (`normalizeColor`, `mineCss`, `classifyRoles`, `pickBrandRoutes`, `mergeColorCounts`, `mergeFonts`) live in a new `@ove/ai` module and are unit-tested against real-world fixtures (Stripe's `#0a2540`/`#635bff` and Söhne come straight out of their CSS variables).
