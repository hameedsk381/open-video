# Changelog

All notable changes to MotionRender (formerly Open Video Engine). The published package is `motionrender` (built from `packages/ove`).

## Unreleased

### Added
- **Explainer scenes in React, the default for `mr make`.** Every scene kind, in every shape (a wide or square video gets the vertical column fitted into the frame, as the stock scenes do), is drawn by React components with up to three drawings each: title (poster, centred), steps (list, ladder, cards, bento), compare (split, stacked, versus), stat (hero, ring, stacked), chart (columns, rows, line), timeline (spine, zigzag), quote (card, pull, typed), flow (funnel, chain), grid (board, spotlight), closing (takeaway, poster), phone (handset, thread), media (frame, split, browser; a picture is declared as an asset, a clip is placed by the build with its rounded corners), plus freeform, hex and pile. A script's scene `variant` picks one, otherwise the scene's own content does (a long point wants stacked, a percentage wants a ring, many bars want rows). Captions, chapters, voice and music are unchanged. `--no-react` keeps the stock scenes; if a stock scene uses something the React view cannot draw, the build falls back to the stock video on its own. `mr make` reports the script's scene count either way. The scenes are built on the React kit (Badge for chips and stamps, ProgressBar for bars, BentoGrid for the bento steps, Typewriter for the typed quote, Waveform on the closing, DeviceFrame for the browser picture): spring physics for every entrance and pop (`springValue`), `NumberTicker` for counting figures, `KineticText` for titles and takeaways, `GlassCard` (in the look's own colours) for cards and `AmbientGlow` behind the calm scenes.
- **A `code` scene:** a file name, up to 14 lines of code and lines picked out one after another, drawn as an editor card (the React kit's `CodeEditor`, or the code typed out in a bare pane with `variant: typed`) and by the stock scenes too. It is in `mr explainer kinds`, the schema and the writer's guide. With it every component of the React kit is in use.
- A closing scene whose title wraps onto a second line no longer runs into its call to action (the line estimate was too optimistic for wide bold fonts).
- `CompositionView` draws captions layers that carry inline cues.
- React scenes make the sounds their stock versions made, and come in with the look's own transition (fade, zoom, wipe or push) instead of a plain fade.
- The explainer writer is sent back a script that is mostly one scene kind (3 or more, half of the video or more) or that has two neighbouring scenes of the same kind and drawing; freeform scenes are exempt.
- The two Dokploy compose files (repo root and `infrastructure/dokploy/compose.yml`) are the same stack again, including the landing page service, and a test keeps them so.

## 0.7.0 (2026-11-14)

### Added
- **Explainer: layout decided by the content.** A `freeform` scene (the script places text, boxes and circles on the 1080×1920 column and times each one) for ideas the stock kinds cannot draw, and a `quote` scene (a source card: who said it, the exact words, an optional stamp). Each scene can set its own `layout` (`card`, `editorial`, or `auto`, which goes editorial when the scene carries a lot of text) and `place`. Scenes are centred between the header and the area reel apps cover, and steps, compare and timeline spacing adapt to how many items they have.
- **Explainer: captions, chapters and music.** Word-timed captions follow the real voice (the Edge voice reports each word's timing; it is kept beside the recording), a segmented progress bar and a "03 / 09" count show where the viewer is, and a quiet music bed (`music`: `calm`, `pulse` or `none`) sits under the voice and drops while it speaks. The beds are two new built-in sounds, `bed-calm` and `bed-pulse`: 16-second chord loops that join themselves without a click. `captions: false` and `chapters: false` turn the first two off; a silent build has no captions or music. A voiced scene that holds longer than 9 s gets a note suggesting a split.
- **A treatment step before the scenes.** The explainer writer and the React agent's direction stage weigh three genuinely different shapes for the video and choose one. `mr explainer write --avoid a/explainer.json,b/explainer.json` and `mr agent --avoid reel-a,reel-b` steer a new video away from the structures already made.
- **README:** an explainer section, "Why MotionRender", agent setup, examples and a comparison with Remotion and HyperFrames.

### Changed
- **Compose writes React wherever the host can run code.** The planner's "json" answer and `OVE_AI_ROUTE` no longer bring back JSON authoring, and a failed React build is an error, not a quiet fallback to a composition. A composition is still written for hosts that cannot run code (the hosted worker), batch variable fields, non-image assets, and when asked (`--no-react`, `--full`, `--json-layers`). `mr agent` has no JSON route.
- **Explainer loudness is mastered to −14 LUFS** (it was −16). The writer asks for 8–16 word spoken lines and seven scenes by default (it was 12–22 words and five).
- **Faster frames.** Each frame goes to the browser page as one JSON string; Playwright was checking and rebuilding every nested object of the argument, about 15 ms of Node time per frame. On a 1080×1920 explainer with 4 pages the per-frame cost fell from 94 ms to 62 ms; output is bit-identical.
- The README, the npm README and the docs use `mr` for commands; `ove` stays as an older alias.
- The published package now has repository, homepage, bugs and keywords.

### Fixed
- **The server-side fetch guard judged IPv6 literals by DNS.** `URL.hostname` keeps the brackets, so `[::1]` went to a lookup that answered differently on each platform. Literals are now classified by the address they carry, including an IPv4 address inside an IPv6 one (mapped, compatible, NAT64, 6to4), and the whole link-local, site-local, multicast and documentation ranges are refused.
- `mr make` treats a file with a `topic` as an explainer script (the example script carries a `version` and was mistaken for a composition).
- Launch reel template: copy is sanitised for quotes, braces and angle brackets, the cursor and light sweep run on the beat's own frames (they never played), and invented claims were removed.
- The studio typecheck (two unused imports) and three integration tests that were stale or racy.

## 0.6.0 (2026-11-10)

### Removed
- **The shipped templates.** The ten ready-made templates (`starter`, `hook-reel`, `kinetic-type`, `product-spotlight`, `logo-sting`, `stats-showcase`, `quote-card`, `event-promo`, `tutorial-steps`, `sale-flash`), their sources and build scripts (`pnpm build:templates`, `pnpm check:templates`), and the template route of the AI composer are gone. `mr ai compose` now has two routes: the planner chooses a JSON composition built from blocks, effects and moves, or (on a machine that runs the code) React. The planner no longer offers `template` or `theme` paths, the capability registry no longer lists templates or themes, and `--template` and `--theme` are gone from `mr ai compose`, `mr init`, the MCP `motionrender_create_video` and `motionrender_init` tools, the compose job and the API. `motionrender_list_templates` is now `motionrender_list_blocks` (blocks and themes). The studio's Assets page has no Templates tab, and Home, Create and Discover open the designs gallery instead of picking a template; a colour theme chosen in Create is sent to the writer as a colour direction in the brief. `retimeComposition` (which stretched a template to the brief's length) and the scene-by-scene voiceover that only template videos got are removed with them; `--narration` now writes one script over the whole video. Not affected: blocks, colour themes (`mr theme`, `mr add`), variables and `--batch`, `mr ai batch --template video.json` (your own composition file), and "template" projects in the studio, which are compositions that still use variables and components.

### Added
- **`mr make`: the whole loop in one call.** Agents used to run validate, compile, several stills, review and render as separate commands (about 95 s of tool time on a four-scene, 24 s explainer, plus a model turn between each). `mr make <explainer.json|composition.json>` (MCP: `motionrender_make_video`) validates, builds, runs the design review and writes one contact sheet of the whole video, and lists every problem at once; the MCP tool also returns the sheet as an image. `--draft` renders a quick half-size MP4 (ultrafast encode, no motion blur; 24.9 s against 55.9 s for the final on that video), `--final` the finished one, and nothing is rendered over review errors. The agent instructions, `AGENTS.md`, `mr setup` and the explainer skill now teach the two-call loop; the single steps remain.

- **Two skills from the community.** The [motion-design skill](https://github.com/LottieFiles/motion-design-skill) (LottieFiles, MIT) now ships in `packages/cli/skills/motion-design` with its licence and a short note on using it in frames (`frames = ms × fps / 1000`, the engine's named curves and cubic Bézier easings, where each principle lives in the engine, and which interface-only sections do not apply to a rendered video). `mr setup` copies it with the other skills and the MCP server lists it as a resource. Its core rules (one personality per video, ease-out entrances and ease-in exits, no linear easing for spatial movement, staggers under half a second, one hero motion per beat, primary plus secondary plus ambient layers) are now in the planner prompt, and the explainer writer is told to match `motion` to the subject. The [ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) (MIT, local, needs Python and FFmpeg) is recommended, not bundled, for footage work beyond `mr ai edit` (HDR tone mapping, stabilising, multicam, lossless cuts, platform checks): the agent instructions and the main skill name it and tell agents to ask before installing it with `npx ffmpeg-skill`, since that writes to the user's skills folder.

### Changed
- `mr init <dir>` starts from a small starter project that now lives in `packages/cli/starter` (and `starter/` in the npm package) instead of a template folder.

## 0.5.2 (2026-11-10)

### Removed
- **Edge is the only speech engine.** The provider-endpoint engine (`OVE_AI_TTS_PROVIDER=native`, `--speech-engine native`, `OVE_AI_SPEECH_MODEL`, `OVE_AI_SPEECH_VOICE`) and the on-device Indic engine (`indic`, `mr ai voices`, `--speech-engine`, `--language` on `mr explainer compile`, `OVE_TTS_DIR`, `OVE_TTS_MIRROR`, the `WITH_INDIC` image argument and the `onnxruntime-node` dependency) are gone, along with their model download and the indic-tiny-tts credit requirement. Narration uses the free Edge voices for every provider: no key, internet needed, word timings from the same call, with retries on a dropped connection and a `voiceRate` for speed. Recordings made earlier stay valid. Provider transcription of audio you supply is unchanged. Anyone who relied on the removed engines needs to switch to Edge voices (for example `hi-IN-SwaraNeural` or `te-IN-ShrutiNeural`).

### Added
- **Explainers no longer all look alike.** A look is now a whole design, not a palette: thirteen of them (the original five plus ocean, terminal, blueprint, candy, sage, newsprint, neon and slate), each with its own type pairing, how text arrives (rise, drop, blur or fade), how scenes change, texture, corner style and headline weight. A new `design` field in a script changes any part of a look, and `colors` still replaces colours. The script writer is now asked to choose the look for the subject (it is shown every look and what it suits, and told not to reach for navy by default); a reply that chooses none gets a look from its topic, so different topics no longer all fall back to the same one. `mr explainer looks [--json]` lists them. `motion`, `radius` and `headWeight` were declared as theme variables but no scene read them; they are now real, and fonts are never asked for a weight they do not have. The default look is unchanged. A new render test measures how far apart the looks are (colour and, separately, shape), so the sameness can be tracked: every designed look is at least 0.076 from its nearest neighbour on shape, against 0.02 to 0.03 for palette-only differences. A new `layout` token (`card` or `editorial`) changes how the title, stat, steps and closing scenes are laid out: `editorial` is flush left with no boxes, hairline rules, large numerals and an accent bar, and the print-like looks (newsprint, sage, terminal, slate) use it. The other scene kinds are drawn the same in every look for now.
- **A steadier Edge voice, with a speed.** The free Edge voice service sometimes drops a connection, which failed a whole explainer build with an unreadable `[object ErrorEvent]`; a failed attempt is now made twice more after a short wait, and the failure says what happened. A new `voiceRate` in an explainer script (-40 to +60 percent) makes the voice faster or slower: +12 suits a lively promo.
- **A sandbox for agents.** `docker build --target agent -t motionrender-agent .` builds an image with the CLI, Chromium and FFmpeg and a `/work` folder that already holds `AGENTS.md`, the skills and the MCP config, running as the unprivileged `node` user; it works in Docker, a sandbox runtime such as OpenSandbox, or CI, so an agent needs nothing installed (`--build-arg WITH_INDIC=1` adds the on-device Indic voices). `mr setup --local` writes MCP configs that start the installed `mr` instead of downloading through `npx`. `scripts/agent-smoke.mjs` tests the whole agent flow from nothing against a packed tarball (`--tarball`), an image (`--docker`) or an installed `mr` (`--installed`). `docs/agent-sandbox.md` covers sizing, the hosts to allow on the network and what is verified.
- **`mr facts`.** Real, sourced facts from the command line, with no key and no AI provider: `mr facts country India,Brazil internet_users`, `mr facts wikipedia "Load balancing"`, `mr facts exchange USD INR`, `mr facts indicators` and `mr facts --lookups file.json`, each with `--json`. It is the same fixed set of sources as the `motionrender_facts` tool, so an agent that only runs shell commands can ground a script too; a slow request is raced by a second one, and it exits with an error when nothing came back. The agent instructions and the ove-explainer skill now say to use it and to leave a number out when a lookup fails.
- **Made for agents: Claude Code, Codex, Cursor and any other.** The agent is the model, so none of this needs an AI key. `mr setup [dir]` makes a folder ready (an `AGENTS.md` and `CLAUDE.md` block that keeps whatever is already there, `.mcp.json`, `.cursor/mcp.json`, `.codex/config.toml` and the skills; running it again changes nothing), `mr init` does the same for a new project, and `mr mcp --config claude-code|codex|cursor|claude-desktop|all` prints the right command or file for each client. New MCP tools: `motionrender_schema` (composition or explainer), `motionrender_explainer_kinds`, `motionrender_explainer_validate`, `motionrender_explainer_compile`, `motionrender_facts`, `motionrender_environment` and `motionrender_init`; skills and schemas are also MCP resources (`motionrender://skill/<name>`, `motionrender://schema/<kind>`). On the command line: `mr explainer kinds [--json]` (every scene kind with a valid example), `mr explainer example`, `mr explainer validate --json` and `mr schema --explainer`. A new `ove-explainer` skill teaches the whole loop. The old Claude Code line in the docs, `claude mcp add motionrender npx -y motionrender mcp`, passed npx's `-y` to claude; it is now `claude mcp add motionrender -- npx -y motionrender mcp`.
- **Real facts for explainers.** `mr explainer write --research` (and the Facts checkbox on the studio Explainer page) looks up what the script needs before it is written: the model names topics, and a fixed list of no-key sources answers them. Wikipedia gives what a thing is, the World Bank gives the latest figure for up to five countries (population, GDP, GDP per person, life expectancy, internet users, inflation, unemployment, urban population), and Frankfurter (European Central Bank) gives exchange rates. The writer may state only those as fact and names the source in the scene, and the facts stay with the script in a new `sources` list so its numbers can be checked. Requests go only to those three hosts, replies are size- and time-limited, and a lookup that fails is reported without stopping the rest. Hosted requests get lookups only when they ask for them.
- **Drawn pictures in explainers.** A media scene can give a `prompt` instead of a `src`: the picture is drawn once with your image model when the video is built, kept in the project's `assets/`, and reused while the prompt stays the same. `mr explainer write --images` (and the Pictures checkbox on the studio Explainer page) lets the writer ask for them, at most two, and a provider that cannot draw is refused with a clear reason. Drawn pictures carry an "AI-generated picture" credit unless the script sets its own.
- **Narration in eleven Indic languages, made on your own machine.** A third speech engine, `indic`, speaks Hindi, Bengali, Marathi, Gujarati, Punjabi, Tamil, Telugu, Kannada, Malayalam, Assamese and Odia in this process with no key, no network and no Python: the released indic-tiny-tts models run as three ONNX graphs through `onnxruntime-node`, the text is prepared by a TypeScript port of the model's own `textnorm` (version 4) and character tokenizer, a four-step Euler flow loop turns it into a mel spectrogram, and an inverse STFT makes the 24 kHz WAV. Word timings are the durations that shaped the audio, so captions cost no transcription. The first line in a language downloads its model (about 88 MB, checksum-verified) into `~/.cache/motionrender/tts`; `OVE_TTS_DIR` moves it and `OVE_TTS_MIRROR` points at a mirror. `ove ai voices` lists what is downloaded, `ove ai doctor` reports readiness, and `--speech-engine indic` / `OVE_AI_TTS_PROVIDER=indic` (aliases `local`, `offline`) switches `narrate`, `voiceover`, `explainer` and the studio's narration to it, with the language from `--language` or the voice's own locale. Numbers are spelled out in Hindi; the other languages read digits one by one for now. The models are CC-BY-4.0 by Sulabh Katiyar, so a video made with them must credit the author.
- **3D models.** A `model` layer draws a `.glb` (or a self-contained `.gltf`) with three.js, centred and fitted to its box so no angle clips. Turn it with `yaw`, `pitch`, `roll` or a steady `spin`, animate those through the `--yaw`, `--pitch`, `--roll` and `--zoom` variables, set the `fov`, `light` and `zoom`, or play the model's own animations by name with `animation`. A frame depends only on its number, so renders repeat exactly; a model file is data, so `--allow-code` is not needed. three.js 0.187 with its glTF loader is bundled into one script that is loaded only for videos that have a model layer: into the render page by the renderer, and into the browser Player from `three-runtime.js` beside it (`threeUrl` overrides). In the studio a `.glb` can be uploaded in the Media tab and placed in a scene. The code builder gets a `model()` helper.
- **Explainer mode in the studio.** A new Explainer page: say what to explain, get a script written by your AI model, edit each spoken line (or the whole script as JSON), choose the shape and look, and make the video, with a recorded voice if you want one. It runs as an `explainer` job (`POST /api/explainer`, with `brief` to write a script, `writeOnly` to get only the script back, or `script` to build it) and the project opens in the editor.
- **Explainers in other shapes.** `aspect` on an explainer script (`9:16`, `4:5`, `1:1`, `16:9`) draws the 9:16 column scaled and centred on the board, header and footer included.
- **Phone and hex explainer scenes.** `phone` shows a short conversation or alerts on a phone screen; `hex` shows a map of hexagon cells with some lit and tagged.
- **Sketch on paths, labels on physics bodies.** A `path` layer takes `sketch` like rectangles and circles (and follows the composition-level `sketch`), and a physics body can carry a `label` that turns with it.
- **p5.js sketches.** A `p5` layer runs a p5.js sketch's `draw(p, args)` once per frame on a p5 canvas (inline `code` or a `src` file, `props`, `resolution`, `seed`). The random and noise seeds are set and the canvas is cleared before every frame, and time is the frame's, so a frame depends only on its number: it repeats exactly, any frame can be drawn alone, and parallel render pages agree. p5.js 1.11 is large, so it is loaded only for videos that have a p5 layer: into a render page by the renderer, and into the browser Player from `p5.min.js` beside it (the studio and dev servers serve it; `p5Url` overrides). Like code layers it runs the composition's JavaScript, so it needs `--allow-code` and AI-written compositions cannot contain it. The code builder gets a `p5()` helper.
- **Physics with matter.js.** A `physics` layer holds a world of bodies (circles and rectangles) that fall, bounce, stack and pile up: set bodies, or emitters that make many with a size, a spread and a rhythm; gravity, walls (`box`, `floor`, `none`), a seed and `substeps`. The world is stepped from the layer's first frame with fixed steps and every frame's positions are kept, so any frame can be drawn on its own, parallel render pages agree, and the same description always makes the same fall. Bodies can be drawn by hand with `sketch`. matter.js is loaded beside rough.js in render pages and in the browser Player. Explainer scripts get a `pile` scene (things falling into a container to show load or overflow), and the code builder gets a `physics()` helper.
- **Hand-drawn shapes with rough.js.** Rectangles and circles take `sketch` (loose double-stroke outlines, a solid fill with hand-cut edges, or pen-stroke hatching), and a whole video takes a top-level `sketch` that reaches every shape unless one says `sketch: false`. Lines come from a seed, so every render draws the same ones; `boil` redraws them every few frames like a hand-redrawn cartoon. rough.js is loaded beside the Lottie player in render pages and in the browser Player. Explainer scripts switch it on with `sketch: true`.
- **Animation craft: squash and stretch, anticipation, wiggle and boil.** Layers take `scaleX` and `scaleY` (animatable) so a landing can flatten and spring back; the easings `anticipate` (wind back, launch past the target, settle) and `bounce` are new; and any numeric animation can carry a `wiggle` (`amount`, `every`, `seed`, `hold`), a frame-exact procedural wobble for idle float, handheld drift or a hand-redrawn boil. The AI prompt knows them, the template kit has `squashLand`, `anticipate` and `wiggle` helpers, `sale-flash` and `product-spotlight` use them, and `docs/motion-principles.md` maps twenty motion principles to what the engine does for each.
- **A brand kit, saved once and applied to every video.** Settings holds one brand: name, colours, heading and body fonts, a contact line and a logo (taken from a website or entered by hand, kept in this browser). Every new video starts with it — the planner and templates use its colours and fonts, the closing scene prints the contact line and signs itself with the logo, placed clear of a reel's UI bands — and a switch turns it off for one video without changing the saved brand. Any finished project gains **Make another**, which opens the composer with its brief and template filled in. Only fonts the renderer ships can be chosen, and a brand still passes the same checks whether it comes from Settings or a website.
- **A new set of ten templates, written with a shared design kit.** The 23 earlier templates are replaced by `starter`, `hook-reel` (9:16), `kinetic-type` (9:16), `sale-flash` (9:16), `product-spotlight` (1:1), `quote-card` (1:1), `event-promo` (4:5), `logo-sting`, `stats-showcase` and `tutorial-steps` (16:9). Each takes a theme (palette, fonts, texture, motion, transition), has described variables, draws in the React view, and carries sound effects. They are generated by `pnpm build:templates` from `scripts/templates/*.mjs` (the kit is `scripts/templates/kit.mjs`), and `scripts/template-sheet.mjs <id>` renders a contact sheet to look at one. `tests/unit/shipped-templates.test.ts` checks every one. Template ids from the old set (`social-reel`, `launch-wide`, `story-tall` and the rest) no longer exist; the AI planner, the studio, the skills and the docs now point at the new ids.
- **MotionRender Studio as a desktop app (`apps/desktop`).** An Electron window around the studio the CLI already serves: it starts one `ai studio` server for the chosen project folder on a loopback port, and adds a folder card to the sidebar (the real path, Reveal, Open Folder) that appears only in the desktop build. The window is sandboxed with context isolation and Node integration off, may only navigate to its own server, and exposes a five-call bridge that takes no paths from the page. A packaged build carries ffmpeg, ffprobe and Chromium (`pnpm --filter @ove/desktop fetch-tools`; the fetched binaries and installers are git-ignored). `pnpm dev:desktop` runs it and `pnpm --filter @ove/desktop smoke` checks it end to end. The window, its loading page and its error page follow the studio's design and theme (the theme is read back from the page and remembered, so the app opens in it without a flash of another colour). Building an installer, macOS and Linux are not yet checked.
- **A production can say what it needs before it exists, and report what is still missing.** `requirements` in `production.json` name a role (a first frame, footage, a voice, a graphic…), an acquisition strategy (retrieve, source, generate, procedural), an optional instruction and a status; the schema rejects one filled by the wrong kind of file, approved with a rejected or superseded asset, or asking for the real thing but filled by a generated one. `productionCoverage` counts approvals, never files: per shot (none, blocked, review, ready), per character, environment and prop, the beats nothing is aimed at, and what is outstanding. `production validate`, the MCP tool and the plan view's next steps show it. Slice 3 of `docs/content-and-assets.md`.
- **References say what they are for.** Character, environment, prop and generation references take `{ asset, role }` as well as a bare asset id (which still works): roles are character, wardrobe, environment, product, style, storyboard, motion, first_frame, last_frame, voice, music, sfx, or the generic reference. The schema checks that a role fits the file (a first frame is not a sound), that a reference is not listed twice in one role, and that a generation has at most one first and one last frame. Slice 2 of `docs/content-and-assets.md`.
- **An asset can say where it came from, what may be done with it, and which bytes it is.** Optional fields on every asset (`provenance`, `rights`, `sha256`, `status`, `parentAssetId`), so existing compositions and productions stay valid. A generated image records its provider, model, prompt and hash, with rights left `unknown` because the provider's terms are not something the engine can know; an upload records its hash in `assets/.manifest.json`. `validate` (the CLI, the MCP tool and `production validate`) now prints notes about assets with no recorded rights, restricted or expired rights, unknown consent, and files that changed since they were recorded, and never fails on them. A version of an asset that is not declared, or an asset that is its own parent, is an error. This is slice 1 of `docs/content-and-assets.md`.
- **The review scales with the length of the video.** It samples about every half second but never more than about 400 frames, puts one frame per scene on the contact sheet when a video has more than 20 scenes (up to 48), and no longer warns that a series of a dozen or more equal-length scenes lacks rhythm. The overlay scene is left out of its rhythm and cut checks.
- **Animated highlighter on rich text.** A text layer's `highlight` (0 to 1, default 1, animatable) sweeps its span `background` highlights in left to right, one span after the next. Drawn by both the canvas runtime and the React view (36 to 38 dB against each other in a check); highlights combined with `split` stay static.
- **`overlay`: layers that stay for the whole video.** A top-level list of layers (a chapter header, a footer, a progress bar) drawn over every scene, with frames counted from the start of the video, so a header is written once instead of repeated in each scene. It takes `{{variables}}`, `repeat` and `use` like any layer list, and scene cameras and transitions never move it. On loading it becomes one last scene named `overlay`, so rendering, audio, assets, the player and the React conversion needed no change; the review leaves it out of the scene rhythm and cut checks.
- **Every video `ove ai compose` writes is a React video.** A template, a scene-by-scene composition or a catalogue block is now drawn by one shared component, `CompositionView` in `@ove/react`, and saved as the same single `react` layer a model-written video is (sound rides beside it as audio layers). The component is MotionRender's own code with the composition as data, so nothing a model wrote runs in it. It draws rectangles, circles and paths (solid or gradient fills and outlines), groups with layout (row or column, gap, padding, alignment), text (wrapped, shrunk to fit, split by word, letter or line, or rich spans with highlights and underlines), pictures, groups, animations, shadows and blur, the scene camera (zoom, drift, shake) and the fade, slide, push, wipe, zoom, dip and blur transitions. Checked against the JSON renderer on shipped templates: text and shapes land on the same pixels (glyph boxes identical to the pixel across sizes; whole frames 28 to 52 dB PSNR, the difference being anti-aliasing). Film grain, background texture, motion blur and the beat grid are carried across, since the renderer applies them to the whole frame. Small text can sit 1 to 2 px higher than the canvas draws it, because the DOM snaps baselines to whole pixels. What it cannot draw yet (video, Lottie, shader and code layers, captions, gradient text, split rich text, grading, mattes and masks, path trimming) keeps its JSON layers, and the compose note names what. `--json-layers` keeps the layers on purpose; the hosted worker still renders JSON, since a React bundle in a tenant's project is code.
- **The video is checked against what the brief asked it to say.** A required line ("end on the line: Ride more.") that no text layer says is put on the last scene, and a text layer that only names a beat ("Hook", "Problem Proof", "Call to Action") is replaced with its beat's line or dropped. Repairs are reported, `--strict` refuses them, and template results get warnings.
- **React is the default route for designed videos** where the host can run it, so a planner that answers "json" no longer turns every brief into text cards. `OVE_AI_ROUTE=planner` or `json` changes that.

### Changed

## 0.3.14 (2026-11-07)

### Added
- **`production.json`: the film's plan, compiled to a composition.** A production manifest records what the video is meant to be — brief, style, script beats, characters, environments, props, a shot list with camera and action, assets, soundtrack, export settings and approvals — and `mr production validate` resolves every character, prop, beat and asset reference at once. `mr production compile` lays the shots end to end as scenes, hands approved takes to the renderer as footage, compiles a shot still in planning into a text card from its on-screen copy, and prints notes for anything it had to fall back on (`mr production compile --output`, MCP `motionrender_production_compile`). - **Content first: a validated script and its data.** A composition can now carry a `content` block — audience, promise, call to action, and the beats with spoken `narration`, on-screen copy, claims, figures and the source ids behind them — and `mr ai compose` writes that script before it designs anything. The planner, template fill, scene writer, narration and captions all derive from it, so copy is never invented during layout. Scenes can name the beat they render with `beat`, and template fills set that link when scenes and beats line up.
- **Scripts are grounded in sources.** The brief is always a source; `--source notes.md|data.csv` adds files; research (on by default, `--no-research` to skip) reads a few public pages the model names, each redirect hop checked by the SSRF guard. Every claim and figure must cite a source id, every cited source must carry a quote copied verbatim from it, and the engine verifies the quote is a literal substring before keeping the script. A rejected script is retried with the exact problem; if none survives, the video is composed without a script rather than with an unverified one. `contentSchema` enforces the same rules on imported or hand-written scripts.
- **`mr script`.** `mr script video/composition.json` prints the script and the data behind it (markdown by default, `--json` or a `.json` output for the import format), and `--set script.json` puts a revised script back after validating it and the whole composition.
- **MCP content tools.** `motionrender_create_video` takes `sources`, `research` and a `script`, and `motionrender_script` exports a video's script or imports a validated replacement.
- **A creative direction before the code.** `ove agent` now asks the model to direct the video first — concept, art direction, palette, type, motion language, sound and a beat structure with seconds — writes it to `direction.json` beside the component, and makes it the section of the coding prompt the video must realize. The stage refines the planner's idea and beats when the planner ran instead of inventing a second art direction. A direction that cannot be produced is reported and the video is still built; `--no-direction` skips the stage, and `runVideoAgent` accepts `direction: false` or a direction you wrote yourself.
- **Briefs no template or block layout can carry are written as React code.** A planner plan of `react` now reaches the agent loop from `mr ai compose` and the local studio: the component is written, compiled, visually reviewed and repaired, and handed back as an ordinary composition (`video.tsx` beside it) so review, narration and rendering are unchanged. Hosted workers are never offered this route, because the brief would otherwise choose the JavaScript the operator's machine runs.

### Changed
- **Templates are a route, not the default.** The planner is no longer told to prefer a template whenever its kind and aspect fit. It chooses template only when the scenes and look already match the brief, JSON for structured and typographic videos the blocks can express, and React when the brief asks for craft no layout carries; it is told never to force a near-miss template. - **Scene-scoped composition: many small calls instead of one big one (`OVE_COMPOSE_STRATEGY=scenes`).** The JSON route can now be composed the way a studio works: one short call agrees the *style contract* with the plan's beats (palette, fonts, a motion move per beat), one small call designs each scene against that contract and a summary of where the previous scene ends, and a deterministic stitch owns everything the models were getting wrong — durations scale the beats to the exact requested total (the model never counts frames), ids, transitions, the house camera push on every scene (which guarantees the craft checks for camera and motion), and a kinetic-split backstop on the longest scene's headline. Each call lands in the provider's fast path (0.2–2 s instead of the 12–75 s stalls big compositions hit on rate-limited gateways), fails independently — a bad scene costs its own retry with the error fed back, not the whole video — and when the renderer's review finds errors, only the scenes that own the failing frames are re-designed with the exact findings (`healScenes`). Any failure in the small-call chain falls back to the proven single-call path, so the mock provider, offline runs and the evaluation baseline are untouched. `composeByScenes` / `healScenes` in `@ove/ai` are unit-tested against a scripted provider (14 tests: contract defaults, duration scaling and the unequal-length jitter, the loader's scene-start rule, keyframe clamping, call order and handoffs, targeted heal).
- **Deep brand extraction from a URL, in the design-system-extractor tradition.** `ove agent --url` no longer guesses a brand from the homepage markup alone: the scraper now mines the site's own stylesheets and `<style>` blocks for the exact tokens the design system is written in — custom properties (a colour declared as `--primary` counts six times more than a stray hex), every colour notation normalized to `#rrggbb` (hex 3/4/6/8, `rgb()`/`rgba()` legacy and modern syntax, `hsl()`), `@font-face` declarations and font stacks (generics, `var()` indirection and length values like the `-0.01em` in `--font-letter-spacing-*` rejected) — and crawls the two highest-signal same-origin brand pages (pricing, product, about first tier; customers, blog, docs second) to confirm the palette across routes. The roles come from the evidence itself: the dominant dark non-vivid colour is the background, near-white the text, and the most-used saturated mid-tones primary, accent and secondary — a vivid indigo is never mistaken for a near-black background. Every extra request is best-effort with a per-fetch timeout, and the merged evidence (colour counts with sources, suggested roles, fonts, pages crawled) feeds the distiller prompt; without a provider the classified roles and fonts become the `BrandPack` directly, so `--url` keeps working offline with `--provider mock`. `ScrapedWebsite` gains additive fields only (`fonts`, `colorCounts`, `roles`, `pages`, `stylesheets`, `links`); the pure miners (`normalizeColor`, `mineCss`, `classifyRoles`, `pickBrandRoutes`, `mergeColorCounts`, `mergeFonts`) live in a new `@ove/ai` module and are unit-tested against real-world fixtures (Stripe's `#0a2540`/`#635bff` and Söhne come straight out of their CSS variables).

### Changed
- **Templates are the primary AI path; compose and agent are secondary.** The planner prompt now prefers a template whenever its kind and aspect fit the brief — even when the length differs (a template keeps its own length) — so the JSON-composition and React routes trigger only for briefs no template fits. `ove ai capabilities` and the planner's capability list say so in the same words, and the docs and the `ove` skill present the template route as the default. - The cache folder has one subfolder per kind (`media/`, `video/`, `sfx/`); entries are marked when used. The dev server's frame cache is capped at 256 MB.
